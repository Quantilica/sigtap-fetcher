## Origem e coleta

- O fetcher baixa, por FTP, o ZIP de cada competência do SIGTAP em `ftp2.datasus.gov.br`, pasta `/pub/sistemas/tup/downloads`. O nome na fonte é `TabelaUnificada_AAAAMM.zip` ou, quando o DATASUS regera a tabela, `TabelaUnificada_AAAAMM_vAAMMDDHHMM.zip`; o sufixo é a data e a hora da geração.
- No bruto, o arquivo fica em `tabelas/` com o carimbo de data da versão baixada (`TabelaUnificada_AAAAMM_vAAMMDDHHMM@AAAAMMDD.zip`).
- Este dataset vem do membro `tb_detalhe.txt` do ZIP (dados, uma linha por registro, largura fixa) e do layout `tb_detalhe_layout.txt`, que dá nome, tamanho e posição de cada coluna. O ZIP traz ainda o layout reunido de todas as tabelas (`layout.txt`), a planilha 'DATASUS - Tabela de Procedimentos - Lay-out.xls' (dicionário oficial) e o `LEIA_ME.TXT` (histórico das mudanças da estrutura). O fetcher guarda o ZIP inteiro; o conversor lê só os membros `tb_*.txt` e `rl_*.txt` e os layouts.
- Conferido em 2026-11-15 pelo tamanho dos membros dos 227 ZIPs publicados (2008-01 a 2026-11, uma competência por mês, sem lacunas), `tb_detalhe.txt` existe e tem conteúdo em todos.

## Conteúdo

- Unidade de análise: um atributo de detalhe vigente na competência.
- Linhas por competência: 12 em 2008-01, 69 em 2026-11; entre as 227 competências convertidas para esta página, de 12 a 69. Cada competência traz a tabela inteira, não só o que mudou.
- Em 2026-11 são 69 atributos (12 em 2008-01); `tb_descricao_detalhe` traz o texto longo de cada um e `rl_procedimento_detalhe` diz quais se aplicam a cada procedimento.

## Variáveis

As descrições seguem a planilha oficial de layout do ZIP ('DATASUS - Tabela de Procedimentos - Lay-out.xls'), conferidas contra os valores observados em 2026-11. Onde os dados diferem da planilha, isso está dito na coluna 'Unidade / códigos'.

## No lake

- Dataset `sigtap/tb_detalhe`, particionado por `competencia` (AAAAMM, texto); um arquivo Parquet por ZIP de competência.
- O conversor lê cada linha de largura fixa com o layout do próprio ZIP, aparando espaços nas pontas; campo em branco vira nulo e texto é decodificado de ISO-8859-1 para UTF-8.
- Colunas numéricas viram inteiros ou decimais conforme o layout; valor que não converte vira nulo. Os valores `9999` que a fonte usa como 'não se aplica' ficam como estão.
- Linhas totalmente em branco são ignoradas. Se um ZIP traz mais de uma versão da mesma competência, só a de maior sufixo `_v` é convertida.
- As colunas `versao` (sufixo `_v` do ZIP) e a partição `competencia` são acrescentadas pelo conversor.
- `dt_competencia` é a coluna do arquivo, mantida como texto.

## Cuidados de uso

- **Cada competência é uma fotografia completa, não um incremento.** Sem filtrar `competencia`, o mesmo registro aparece uma vez por competência (esta tabela soma 7.876 linhas nas 227 competências convertidas, contra 69 em 2026-11). Filtre uma competência ou compare competências explicitamente.
- Os códigos de detalhe acompanham as regras de cada competência; atributos podem ser criados ou retirados, então use sempre a mesma `competencia` ao juntar.
- **Junte sempre pela mesma competência.** Códigos, nomes e valores mudam de uma competência para outra; unir tabelas de competências diferentes dá resultados que nunca existiram no SIGTAP.

## Exemplos

Quantos procedimentos têm cada atributo de detalhe na competência mais recente.

```python
import duckdb

duckdb.sql("""
    SELECT d.co_detalhe, d.no_detalhe, count(*) AS procedimentos
    FROM read_parquet('lake/sigtap/rl_procedimento_detalhe/**/*.parquet', hive_partitioning = true, union_by_name = true) x
    JOIN read_parquet('lake/sigtap/tb_detalhe/**/*.parquet', hive_partitioning = true, union_by_name = true) d
      ON d.competencia = x.competencia AND d.co_detalhe = x.co_detalhe
    WHERE x.competencia = '202611'
    GROUP BY 1, 2
    ORDER BY 3 DESC
    LIMIT 10
""").show()
```
